## Текущее состояние

Проект реализован как простой статический сайт без сборщика и внешних зависимостей. Сайт открывается через `index.html` из корня репозитория и подходит для публикации на GitHub Pages.

Цель сайта — показать продуктовый UX-подход к сложным сценариям: для задания 1 это переосмысление первого пользовательского сценария DMcloud, для задания 2 — быстрый аудит мобильного приложения DataMobile с учетом условий работы на ТСД, для задания 3 — оценка первого знакомства с документацией, для задания 4 — концепция единого центра уведомлений.

## Задание 2: UX-аудит DataMobile

Источник контекста: `https://data-mobile.ru/datamobile/`

Аудит сфокусирован на рабочих сценариях DataMobile: выбор операции, сканирование, исправление ошибок, работа при нестабильной связи и повторяющиеся действия на ТСД.

В аудите учтены особенности использования:

- небольшие экраны ТСД;
- работа одной рукой;
- интенсивные повторяющиеся операции;
- offline/online-режимы;
- нестабильная связь;
- необходимость быстро исправлять ошибки сканирования;
- аппаратные кнопки сканера;
- работа новых и опытных сотрудников.

Страница аудита содержит 6 наблюдений. Для каждого наблюдения указаны проблема, причина, возможное решение и приоритет по шкале:

- 🔴 Критично;
- 🟠 Желательно исправить;
- 🟢 Можно улучшить.

## Задание 4: Центр уведомлений DataMobile

Страница описывает единый центр для системных уведомлений и сообщений из учетной системы.

Содержание:

- приоритеты уведомлений: критичные, важные, информационные;
- правила прерывания работы и отложенных сообщений;
- способы сообщить пользователю о новом уведомлении на ТСД;
- история уведомлений со статусами;
- обязательные состояния центра уведомлений;
- сценарий одновременного прихода трех уведомлений;
- короткий блок использования AI.

## Ключевая продуктовая идея

Новый пользователь DMcloud быстрее доходит до первой ценности, если после регистрации видит не пустой кабинет и разрозненные разделы, а управляемый onboarding-сценарий с диагностикой состояния аккаунта.

Первой ценностью считается состояние, когда:

- лицензия добавлена или оформлена как trial;
- устройство подключено к личному кабинету;
- лицензия закреплена за устройством;
- лицензия активирована;
- пользователь понимает следующий шаг: настройка ПО или работа с группами устройств.

## Основное UX-решение

Предложен guided setup поверх существующих сущностей DMcloud.

Сценарий первого запуска:

1. Приветствие и диагностика состояния аккаунта.
2. Выбор стартового пути: купленный сертификат или trial.
3. Добавление лицензии или выбор trial-продукта.
4. Подключение устройства через PIN/QR.
5. Привязка лицензии к устройству.
6. Активация лицензии с выбором даты начала.
7. Финальное состояние готовности и переход к настройкам.

## Почему выбран такой подход

Подход минимально вмешивается в существующий продукт, но закрывает главный разрыв первого опыта: пользователь не должен самостоятельно собирать порядок действий из нескольких инструкций.

Решение сохраняет текущие разделы DMcloud, но добавляет сценарный слой, который:

- показывает следующий шаг;
- объясняет смысл действия;
- учитывает состояние аккаунта;
- разделяет trial и подписочную лицензию;
- объединяет действия в веб-кабинете и на ТСД;
- формулирует понятный финальный результат.

## Важные сценарные правила из документации

- Trial-лицензия бесплатная, действует 14 дней, сразу активируется и привязывается только к одному устройству.
- Trial-лицензию нельзя перенести на другой ТСД.
- Подписочная лицензия после покупки добавляется в личный кабинет через код сертификата.
- Временную лицензию нужно привязать к устройству через выбор устройства в строке лицензии.
- Для активации временной лицензии пользователь выбирает дату начала, а дата окончания рассчитывается автоматически.
- Устройство добавляется в DMcloud через приложение на ТСД с использованием PIN-кода или QR-кода из личного кабинета.
- После успешного подключения устройство появляется во вкладке «Устройства» в DMcloud.
